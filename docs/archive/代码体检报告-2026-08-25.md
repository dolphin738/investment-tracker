## 一、高风险发现

### REP-001 安全隐患：`GET /api/token` 未鉴权签发 JWT，并自动创建演示账户

- 维度：安全隐患（遗留调试端点进入生产）
- 位置：backend/app/modules/health/router.py:75-92（注册于 backend/app/main.py:97）
- 证据：

```python
@router.get("/token")
async def issue_demo_token(db: AsyncSession = Depends(get_db)) -> dict:
    # 仅用于冒烟测试便捷获取 token（真实签发在 auth 模块）。
    user = (await db.execute(select(User).where(User.id == "demo-user-id"))).scalar_one_or_none()
    if user is None:
        db.add(User(id="demo-user-id", email="demo@example.com",
                    password_hash=hash_password("demo-pass"), name="Demo"))
        await db.commit()
    return {"token": create_access_token("demo-user-id", "demo@example.com")}
```

- 影响范围：该路由随 health.router 无条件挂载，生产 Docker 镜像同样生效。任何能访问 3000 端口的人无需凭据即可获得合法登录态 token，进而调用全部普通用户接口；若与 demo 邮箱发生用户冲突或误提权，影响升级。
- 建议动作：删除 `/api/token` 端点（契约冒烟改由 pytest 内直接调用 `create_access_token`），或加环境开关仅测试构建启用。
- 风险等级：高
- 关联：功能验收表 BE-HLTH-07 已裁决"阶段 3 删除"，与本条互相印证。

### REP-002 安全隐患：`JWT_SECRET` 危险默认值且启动不校验强度

- 维度：安全隐患（硬编码默认密钥）
- 位置：backend/app/core/config.py:23（JWT_SECRET）、config.py:28-30（DATABASE_URL 弱默认）
- 证据：`JWT_SECRET: str = "change-me-in-prod"`；`get_settings()` 直接返回默认值；docker-entrypoint.sh 不做检查，Dockerfile 运行命令为 `--env-file backend/.env`，漏传即静默回退默认。
- 影响范围：部署者忘配 .env 时密钥为人尽皆知的 `"change-me-in-prod"`，任何人可离线伪造任意用户（含已知 admin 用户 id）的 JWT，完全接管系统；与 REP-001 叠加构成未认证到服务器沦陷的完整链路。
- 建议动作：启动时校验——`JWT_SECRET` 等于默认值或长度不足则拒绝启动（至少 FATAL 日志告警）；同理校验 DATABASE_URL 不含弱默认口令。
- 风险等级：高

### REP-003 安全隐患：`LOCAL_COMMAND` 定时任务类型是内置任意命令执行通道

- 维度：安全隐患（设计特性型命令注入面）
- 位置：backend/app/core/scheduler.py:171-194、backend/app/modules/admin/schedule.py:44-50
- 证据：

```python
command = (params.get("command") or "").strip()
result = await asyncio.to_thread(
    subprocess.run, command,
    shell=True, stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
    timeout=_LOCAL_COMMAND_TIMEOUT, check=False, text=True, errors="replace",
)
```

admin/schedule.py 将 LOCAL_COMMAND 标记为 creatable=True，POST /api/admin/tasks 可创建并 trigger 立即执行。

- 影响范围：权限链本身收口正确（create_task/trigger_task 均 require_admin，已逐一核对），单独看不构成漏洞；但它是产品内置 RCE 原语——admin 会话一旦被劫持（token 泄漏或 REP-002 密钥伪造），攻击者一步拿到容器内 shell，使所有 admin 凭据类漏洞后果升格为服务器沦陷。
- 建议动作：增加环境开关（如 ENABLE_LOCAL_COMMAND 默认 false）；或执行白名单目录；或在运维文档显著标注信任模型。
- 风险等级：高（链式放大）

## 二、中风险发现

### REP-008 安全隐患：INTERNAL_CLEANUP_TOKEN 默认弱值

- 位置：backend/app/core/config.py:54、backend/app/modules/internal/router.py:28-41
- 证据：`INTERNAL_CLEANUP_TOKEN: str = "change-me-internal"`；`_assert_internal_token` 用 `!=` 比较；对应端点 POST /api/internal/cleanup/accounts 触发 CleanupService.physical_purge() 物理清除。
- 影响范围：端口暴露且未改默认值时，任何人携带默认 token 即可触发不可逆物理清除（软删除过保留期的数据永久消失）。时序侧信道在本部署形态下不可实际利用，不单独计项。
- 建议动作：启动检测默认值并拒绝启动/告警；比较改用 `secrets.compare_digest`。
- 风险等级：中

### REP-009 安全隐患：SSRF（HTTP 回调 url 与 provider base_url 无目标校验）

- 位置：backend/app/core/scheduler.py:197-209（HTTP_CALLBACK 任务类型）、backend/app/services/market_data_sync.py:431-468、backend/app/modules/admin/router.py:51-58
- 证据：`url = (params.get("url") or "").strip()` 后直接 `client.request(method, url)`；provider 的 base_url 仅校验"是非空字符串"即拼入请求 URL。
- 影响范围：两者均 admin-only 配置，非匿名可利用；但结合 REP-001/REP-002 获得的会话即可让服务器探测内网、命中云元数据地址、经 job_run_logs 带出部分响应信息。单机自部署形态利用价值中等。
- 建议动作：scheme 白名单 http/https；可选禁止环回/链路本地网段（provider 允许私网时提供显式开关）；timeout 上限约束。
- 风险等级：中

### REP-010 安全隐患：公开注册 + 登录无限速 + 密码/邮箱零策略

- 位置：backend/app/modules/auth/router.py:27-29、backend/app/schemas.py:20-23、backend/app/services/user.py:61-74
- 证据：`email: str`（非 EmailStr）、`password: str`（无长度下限）；全项目搜索限流相关关键词仅行情接口有限流，登录失败无限速。
- 影响范围：服务暴露公网时可无限注册账户、持续爆破登录（唯一减速是 bcrypt cost）；纯内网自用基本不可利用——据此评中而非高。
- 建议动作：登录失败按 IP+账号限速；注册加环境开关供单用户部署关闭；email 改 EmailStr、password 加最小长度。
- 风险等级：中

### REP-011 安全隐患：JWT 7 天有效期且无吊销机制

- 位置：backend/app/core/config.py:25、backend/app/core/security.py:31-46
- 证据：`ACCESS_TOKEN_EXPIRE_MINUTES: int = 60 * 24 * 7`；get_current_user 仅校验签名/过期 + 用户存在未软删除，无 token 版本校验；改密后旧 token 依旧有效。
- 影响范围：token 泄漏后有 7 天窗口且无法通过改密止损。角色降权有库级实时校验防护（这点做得好）。
- 建议动作：User 表加 token_version（或以 password_hash 前 8 字符作 claim 比对），改密/注销时递增；有效期缩至 1 天配刷新。
- 风险等级：中

### REP-012 废弃接口：refresh-async 端点三方零调用

- 维度：废弃依赖与接口
- 位置：backend/app/modules/portfolio/router.py:97
- 证据：关键词 `refresh-async` 在 web/src、web/e2e、backend/tests、backend/scripts 全部零命中（唯一出现即 router 定义行）；前端 portfolio-price.api.ts 仅封装同步版 `/prices/sync` 与 `/prices/sync-status`。
- 影响范围：异步刷新链路（202 + 轮询）整体无人消费。
- 建议动作：确认产品无规划后删除该端点及其 service 支撑代码。
- 风险等级：中
- 关联裁决：验收表 BE-PF-08 将其标为 P0 且无测试（REP-005 第 7 条）。两条联动二选一：删端点（同时从验收表移除 BE-PF-08），或保留并补 202 契约测试。
