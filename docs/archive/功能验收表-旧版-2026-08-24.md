# 功能验收表（阶段 1 交付物）

> [!info] 用途与地位
> 本表是《AI代码清理与瘦身实施计划》阶段 1 的产出物，是后续所有删除操作的「免死金牌」：
> - **R1.2** P0 链路对应的代码为「承重墙」，任何删除方案不得触碰其主路径
> - **R1.3** 每轮删除完成后必须对照本表逐项复核，复核记录附于 PR 描述
> - **R1.4** 复核发现失败项立即回滚本轮全部改动

- 基线版本：分支 `cleanup/phase-0`（基线 tag `pre-cleanup`）
- 生成日期：2026-08-24
- 生成方法：AI 遍历前端全部注册路由页面源码 + 后端 `main.py` 挂载的全部路由模块源码逐条记录；只记录代码真实存在的行为，禁止推测；拿不准处标注 [待人工确认]
- 规模统计：前端 17 组 107 个功能点；后端 21 个模块 122 个接口
- 查证轮次：初稿标记的全部疑点已经第二轮定向源码查证消解并回填正文（证据指针见各行备注与第四部分摘要）；唯一遗留设计意图裁决项为 BE-013/QB-12，已于 2026-08-24 裁决为缺陷（按现状锁定，修复纳入后续轮次，见 4.3）
- 重要事实：`docs/openapi.json` 已严重过时（缺 9 组端点、含 2 个已删除端点），不可作为验收依据；本表以当前源码为准

## 优先级定义与分布

| 级别 | 定义 | 本项目典型代表 |
| --- | --- | --- |
| **P0** | 出错即造成资损或数据丢失 | 认证边界、流水/交易/价格/余额/快照写入、组合删除与清空、导入落库、账号注销恢复、物理清理、重算引擎 |
| **P1** | 用户高频使用的主流程 | 概览/持仓/出入金/分析各页查询展示、组合管理、行情同步、偏好设置、导出 |
| **P2** | 低频或辅助功能 | 契约路由、客户端日志上报、模板下载、头像上传、持久化细节 |

# 第二部分 后端 API 接口验收清单

## B-00 全局约定

- **响应信封**：除文件直出端点外，所有响应经 EnvelopeRoute 包裹为 `{code, data, message}`；code=0 成功
- **业务码表**：0 成功 / 1001 未认证 401 / 1002 Token 过期 403 / 1003 邮箱已注册 409 / 1004 密码错误 400 / 1006 文件无效 400 / 1007 冷静期中 409 / 1008 未处于注销 409 / 1009 恢复超期 410 / 2000 校验失败 400 / 3001 不存在 404 / 4001 角色不足 403 / 5000 内部错误 500
- **共享错误**：受保护端点无/坏 token → 401/1001，过期 → 403/1002；角色不符 → 403/4001；归属隔离统一 404/3001（get_portfolio，不泄露存在性）；请求体校验失败 → 400/2000
- **序列化**：金额类 DecimalStr 序列化为字符串；分页信封 `{items, total, page, pageSize}`；重算元数据 `{recalculation: {fromDate, affectedDays, skippedManualDays}}`
- **权限标记**：公开 / JWT（任意登录）/ admin / admin+auditor / Internal（X-Internal-Token）
- **注册顺序敏感**（回归重点）：aggregation 先于 portfolio 注册（否则 /summary 被 /{portfolio_id} 吞掉）；GET /api/admin/quote-providers/interfaces 先于 GET /{provider_id}

## 4.3 唯一遗留人工裁决项（已于 2026-08-24 裁决）

| 编号            | 事实（已证）                                                                                                                                                                                                  | 裁决结论                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| BE-013（QB-12） | GET /api/auth/me 实际返回 7 字段缺 createdAt；GET /api/auth/profile 返回 8 字段含 createdAt；两者 response_model 均声明为含必填 createdAt 的 UserPublicOut，因 EnvelopeRoute 直返 Response 绕过 response_model 序列化，OpenAPI 文档与实际输出不一致 | 已裁决为缺陷而非有意设计；本表按现状记录并锁定，修复纳入后续轮次 |

裁决依据与影响面补充查证（2026-08-24）：auth 模块共 8 处内联构造 user dict，7 处缺 createdAt（register/login/restore/me/PATCH profile/PATCH password/PATCH email），仅 GET /profile 完整（router.py:30-38,47-55,65-73,83-91,105-114,126-134,148-156,171-179）。判定为遗漏而非设计的依据：GET /profile docstring 自称「与 PATCH /profile 对称」但实际不对称（router.py:101）；前端 lib/types.ts:413 契约声明 createdAt 必填；AccountInfoCard.vue:71 实际渲染「注册于」字段。当前风险：靠前端可选链防御未出错，但 login/改密/改邮箱响应 user 写入 localStorage 形成缺字段脏缓存（AccountInfoCard.vue:9-10 注释自认）。修复方案：7 处 dict 各补 `"createdAt": u.created_at.isoformat() if u.created_at else None`（与 router.py:113 写法一致）；EnvelopeRoute 绕过序列化故新增字段对现有消费方零风险。
