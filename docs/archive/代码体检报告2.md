## 一、安全隐患（维度 6）

### REP-001 | 高 | JWT 密钥与内部令牌存在弱默认值且无启动校验

- **位置**：backend/app/core/config.py:23（`JWT_SECRET: str = "change-me-in-prod"`）、config.py:54（`INTERNAL_CLEANUP_TOKEN: str = "change-me-internal"`）
- **证据**：代码通读；`.env.example:2` 注释明确要求"JWT_SECRET 必须为 ≥32 字节随机串"，但 Settings 类无任何启动时校验（无 validator / lifespan 检查），漏配 `.env` 时应用静默以弱密钥运行
- **攻击场景**：生产部署忘记注入环境变量 → JWT 可被任何知道默认值的人伪造 → 全部认证边界失效（P0 链路）；INTERNAL_CLEANUP_TOKEN 同理可被伪造调用物理清理端点
- **建议动作**：启动时（lifespan 或 pydantic validator）检测到默认值即拒绝启动（生产模式）或输出醒目告警；属缺陷修复，不属删除类
- **影响范围**：认证全部端点（BE-AUTH 组）+ internal cleanup（BE-INT 组）

### REP-002 | 高（已裁决，阶段 3 删除池）| GET /api/token 公开无鉴权签发 demo token

- **位置**：backend/app/modules/health/router.py:75-92
- **证据**：《功能验收表》第三部分裁决记录 #1，BE-HLTH-07
- **建议动作**：按既定裁决在阶段 3 删除，冒烟改走 `/api/auth/login`。此处仅登记不重复裁决

### REP-003 | 低 | .env.example 携带真实格式密钥样例

- **位置**：backend/.env.example:5（`JWT_SECRET=YeYdWyWAvxCrQ169N5ITu2ZlwqRmsoTIH6O7v9Li2-E`）
- **证据**：文件通读；虽为示例文件，但该串具备真实熵，存在被直接复制到生产的惰性风险
- **建议动作**：替换为 `CHANGE_ME_TO_RANDOM_32BYTE_SECRET` 式占位符
