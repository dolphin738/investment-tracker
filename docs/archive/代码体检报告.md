## 发现清单（按风险等级降序）

### 风险：高

**REP-001 | 安全隐患 | `backend/app/core/config.py:23`**
证据：`JWT_SECRET: str = "change-me-in-prod"` 硬编码弱默认值；全局检索 `JWT_SECRET` 在 `app/` 内仅此定义处与 `core/security.py` 读取处，无「默认值 + 生产环境 → 拒绝启动」的强校验。攻击场景：生产部署漏配环境变量时，任何知道该公开默认值的人可自签 HS256 token 冒充任意用户（含 admin），完全绕过认证。
影响范围：全部鉴权接口、全部业务数据。
建议动作：应用启动时增加哨兵校验（检测到默认密钥即 fail-fast），或在文档化部署清单中强制该项；不改默认值行为本身以免破坏本地开发流。
风险等级：**高**

**REP-002 | 安全隐患 | `backend/app/core/config.py:54`**
证据：`INTERNAL_CLEANUP_TOKEN: str = "change-me-internal"` 弱默认值；`modules/internal/router.py:28-30` 校验逻辑为「header 与该值相等即放行」，无生产环境强制改值机制。攻击场景：生产漏配时，任何能访问 `/api/internal/cleanup/accounts` 的内网请求方可触发账户物理清除（`CleanupService.physical_purge`）与头像文件批量删除，且该端点不走 JWT。
影响范围：账户数据物理删除、头像存储。
建议动作：同 REP-001，启动时哨兵校验默认值；或支持「留空 = 端点直接 403 关闭」（当前留空已 403，见 router.py:29，可在文档强调此用法）。
风险等级：**高**
