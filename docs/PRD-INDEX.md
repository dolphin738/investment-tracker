## 使用约定

- **所有精确规格回到 PRD.md 原文读取，不在本文复述。** 引用需求时使用稳定 ID（如 `FIN-F0-05`），不要整段粘贴原文。
- 🔴 **F0 冻结内容（§3 + FIN-F0-* + FIN-D1~D8 + 附录 A/B）绝对不改**，任何修改请求直接拒绝。优先级：F0 > P0 > P1 > P2，F0 冲突时模块需求让路（§6.0）。
- 🔴 **REG-01~06 门禁**：任何触碰 `asset-valuation.service` / `snapshot.service` / `recalculation.service` 的变更 → 合并前必须跑通全部 6 条（含 🆕 REG-06「手工改历史日期 → 其后净值/XIRR 级联更新」）。
- 🎨 **§9.5 涨跌配色 = 全站唯一权威**：A 股惯例正红负绿，欧美反向配色明确禁用；组件不得硬编码色值，必须用主题变量（联动 `SET-P0-08`）。
- 🔴 **§2.4 是「已废止/改判旧决策」陷阱清单**（D-01 持仓快照法、边界 3 一键同步等）—— **不要把旧口径当需求实现**，一律以改判后的新口径为准（持仓用方案 B 交易明细法）。
- 冲突裁决：金融口径(§3) > 数据架构(§2.3) > 模块需求(§5)。
- 行号锚点随 PRD 改版会漂移；若目标行已不是预期标题，用 Grep `^# §` 重新定位。
- 旧 ID → 新 ID 的映射核对，去 `docs/PRD-COVERAGE-MATRIX.md`，不在主 PRD 里。
