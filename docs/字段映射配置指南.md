# 字段映射配置指南（大白话版）

> 一份给「想接一个新数据源、又不想看代码」的人看的说明书 · 看完能自己配、自己试、自己排查

**一句话记住**：字段映射就是告诉系统——「你返回的一大堆数据里，哪个字段是股票代码、哪个是价格、哪个是日期」。系统只认 5 种标准身份（叫 slot），你不用记英文，下拉选就行。

---

## 一、它到底解决什么麻烦

以前系统用 4 个写死的列（比如「代码在那列、价格在那列」）来认数据。问题是：不同的数据源返回的 JSON 长得千奇百怪，想多认一种含义，就得改列、改所有用到它的地方。

字段映射把这件事变成一张**可以随便增删的表**：你每行写一条「从返回数据里取某个值，对应我系统里的『代码/价格/日期』等标准身份」。系统只认底下这 5 个标准身份，你填表就行，不用碰代码。

> **在哪配？**
> 金融数据接口页（接口 API 来源 / 行情提供方）→ 点某个接口「编辑」→ 弹窗里有 `字段映射` 页签（配每一列怎么取）+ `响应解析` 页签（配数据源是 JSON 还是文本分隔）。

---

## 二、一行映射里，四个东西各管什么

表格里**每一行**就是一个「字段映射」。这一行里有四个关键东西，很多人会搞混，先记牢：

| 东西 | 大白话 | 举个例子 | 能不能不填 |
| --- | --- | --- | --- |
| **展示名**（label） | 给人看的「昵称」，比如「最新价」 | 最新价 / 证券代码 | 可以空，纯展示，系统不校验 |
| **逻辑名 key** | 这行在系统内部的「身份证号」 | `price` / `latest_price` | 可以空（留空自动按身份派发） |
| **取值路径 source** | 「去数据哪个位置把值掏出来」的地址 | `data.last` / `code` | 不能空，保存会报错 |
| **槽位 slot** | 这个值的「身份」（是代码？价格？日期？） | `code` / `price` | 可以空 = 选「仅展示」，不参与同步 |

**打个比方（记这个就够了）：**
仓库发来一箱货。
- `source` = 去仓库**哪层哪格拿货的地址**；
- `key` = 这箱货的**内部编号**（机器靠它认）；
- `label` = 贴在箱子上的**中文标签**（人看着方便）；
- `slot` = 这箱货的**身份**（是「代码」还是「价格」），决定了它该交给谁用。

## 三、取值路径（source）怎么写——最常见踩坑点

把接口返回的「每一行」当成一棵树，`source` 就是「从哪条路走下去把值取出来」。只有 5 种写法：

| 写法 | 意思 | 举例 |
| --- | --- | --- |
| `code` | 顶层有个叫 code 的字段 | 返回 `{"code":"600519",...}` 就写 `code` |
| `0` / `1` | 单行是数组时取第 0 / 1 个 | 返回 `["600519","茅台"]`，代码写 `0`、名称写 `1` |
| `a.b` | 一层层往里走 | 返回 `{"data":{"last":12.3}}` 写 `data.last` |
| `items[0].code` | 数组里取下标用方括号（不会和上面的「字面 0」混淆） | 返回 `{"items":[{"code":"600519"}]}` 写 `items[0].code` |
| `a\.b` | 字段名本身带点，用反斜杠转义 | akshare 列名 `2024.06` 写成 `2024\.06`（表示名叫 2024.06 的字段） |

> **约束**：路径最多 5 段；空了保存会报错。输入框旁边有**实时红字校验**，写错立刻提示。

### 一个完整例子（直接照抄改）

```json
{"key":"code",   "label":"代码",   "slot":"code",   "source":"code",       "type":"string",  "required":true},
{"key":"name",   "label":"名称",   "slot":"name",   "source":"name",       "type":"string"},
{"key":"price",  "label":"最新价", "slot":"price",  "source":"data.last",  "type":"decimal", "scale":2, "unit":"yuan"},
{"key":"date",   "label":"日期",   "slot":"date",   "source":"trade_date", "type":"date", "date_format":"%Y-%m-%d"},
{"key":"notice_title", "label":"公告标题", "source":"title", "type":"string"}
```

前 4 行绑了身份 → 参与同步；最后一行**没绑身份** → 只展示、不参与同步。选了 `decimal` 才出现「小数位」，选了 `date` 才出现「日期格式」。

---

## 四、高级区几个坑（写之前看一眼）

- **逻辑名 key**：小写字母开头、只能含小写字母/数字/下划线、接口内不能重名（规则 `^[a-z][a-z0-9_]{0,63}$`）。留空会自动按身份派发。注意 `key:"_code"` **不合法**（下划线不能开头）。
- `source:"_code"` 是另一回事：这是「文本分隔」源（如腾讯财经）注入的特殊键（带前缀的代码），和 key 命名空间独立，别混。
- **单位**：`none` / `yuan`(元) / `wan`(万) / `pct`(%)。
- **小数位**：仅 decimal 有效（0~8）。
- **日期格式**：仅 date 有效（如 `%Y-%m-%d`）。

---

## 五、数据源不是 JSON 怎么办（响应解析页签）

- **JSON（默认）**：直接按上面的 source 取。
- **文本分隔**（腾讯财经用 `~`）：额外填 编码（腾讯填 `gbk`）、分隔符（`~`）、行提取正则、代码参数名（腾讯填 `q`）。

---

## 六、怎么确认配对了——去试调

先说清楚：**测试面板不在「编辑接口」弹窗里**。编辑弹窗只有 4 个页签（基本信息 / 字段映射 / 响应解析 / 高级设置）。试调有两个入口：

### 入口 A · 手动试调（最常用，看命中率）

位置：**管理后台页 →「证券主数据 + 接口测试」板块（右栏的「接口测试」面板）**

1. 顶部下拉**选接口**；
2. 参数区**增删 / 填写键值对**（如 `date=20231231`，面板对易错参数有提示，比如报告期只收季度末 `0331/0630/0930/1231`）；
3. 「代码」框可选填测试代码（如 `600519,000001`，逗号/空格/换行分隔）；
4. 点**「执行测试」按钮（带 ▶ 图标）**。

点完下方出结果：状态 / 耗时 / HTTP 码，然后是**「逐槽位命中率」表**——列有：槽位、字段、中文名、**命中数**、**缺失数（红色即异常）**、示例值。再往下是原始响应（可查找高亮、复制）。

> 这个命中率表就是验证你映射对不对的地方：某身份「缺失」是红色且数字高，说明那个 slot 的 source 写错了，或返回里压根没这个字段。

### 入口 B · 一键预填（自动实调 + 生成映射）

位置：**接口弹窗 →「字段映射」页签 → 底部「一键预填」按钮**。它会对接口做一次**真实调用**，再按返回结构生成字段映射行，你人工校正后保存。

**编辑已有接口**：直接用该接口当前的参数实调一次。行为与以前一致。

**新增接口（不必先保存）**：只要填好「调用路径」并选好提供方，就能直接点预填——后端按 endpoint 实调一次，不需要先存一版占位接口。两种接入方式的行为略有不同：

| 提供方接入方式 | 实调行为 | 额外可填 |
| --- | --- | --- |
| SDK（akshare） | 按「调用路径」里的 akshare 函数名调用；参数区留空则按该函数的**签名默认值**调用，填了参数就按你填的调 | —— |
| HTTPS | 按「调用路径」拼到提供方配置的 `base_url` 上发起请求，并带上弹窗当前的「响应解析」设置 | **探测用测试代码**：逗号分隔（如 `sh600519,sz000001`）。调用路径以 `=` 结尾的内联形态（如腾讯财经 `q=`）必须填；否则可能拿不到数据 |

**按钮什么时候可点**：调用路径已填 **且** 提供方已选（SDK / HTTPS 均可）。两个条件任一不满足，按钮置灰并提示缺什么。

**安全边界（可放心点）**：预填是一次**只读探测**——不写入数据库、不计入接口失败计数、不重试也不占用限流配额；探测失败会直接告诉你原因（缺 `base_url`、地址被安全策略拦截、上游 5xx / 401、连接失败、超时等），不会污染现有同步。

> **提示**：猜不出语义的列会落到「仅展示」（不参与同步），人工校正即可；探测结果只作草稿，保存前请核对。

## 七、重点：标准身份（slot）只有 5 个，超了会怎样

系统只认这 5 种身份，因为「每种身份背后都必须有一段代码来消费它」。多出来的身份没有代码接，写了也没用，所以干脆在保存时拦住。

| 身份 slot | 含义 | 哪个用途必填 |
| --- | --- | --- |
| `code` | 证券代码 | 4 种用途全必填 |
| `name` | 证券名称 | 主数据（缺失只是不展示，有兜底） |
| `exchange` | 交易所 | 主数据（缺失按代码前缀推断，有兜底） |
| `price` | 价格 / 收盘价 | 行情（硬必填） |
| `date` | 日期 | 行情（硬必填） |

> 保存会**直接打回**，报错类似「slot 非法（白名单：code/name/exchange/price/date）：volume」。正确做法不是硬写，而是把那一行 **slot 留空、选「仅展示」**——这样它不参与同步，但能在测试面板里看到取数对不对。

## 八、老接口需要改吗

**不用。** 如果字段映射留空，系统自动用旧的 4 列（代码列、价格列等）+ 日期字段合成，行为和以前完全一致。只有**新接入**、或想适配复杂嵌套结构的接口，才需要配这张表。

---

**最后再记一句**：配完别凭感觉，去「接口测试」面板点一下执行测试，看命中率表——哪个身份是红色缺失，就回去改那一行的 source。配错只在测试时暴露，不会悄悄污染数据。
