## 3. 🔴 新发现：特别分红被静默丢弃（本轮最重要发现）

### 3.1 事实

`parse_cninfo_row`（`dividend_cninfo_parse.py:85-87`）的第二个跳过条件：`parse_report_period_cn(报告时间) is None → return None`。而**巨潮的「特别分红」「股改分红」行，「报告时间」为空**，于是整行被丢——**即使该行有真实现金派息**。

| **600519** | `None` | **特别分红** | **2022-12-27** | **219.1** | **21.91** | **窗内 ✗ 被丢** |
| **600519** | `None` | **特别分红** | **2023-12-20** | **191.06** | **19.106** | **窗内 ✗ 被丢** |

| 000001 | `'1995年报'` | 年度分红 | 1996-05-27 | 0.0（送股5+转增5） | 0 | 窗外（符合 A1） |

### 3.2 影响量化（留存窗内「每股派息合计」对比）

| 证券 | A 现状（仅可解析行） | B 补入无报告期派息行 | 低估额 | 低估比例 |
|---|---|---|---|---|
| **600519 贵州茅台** | **160.32323 元/股** | +41.016 元/股 | **41.016 元/股** | **25.6%**（B/A = 1.2558） |
| 000001 平安银行 | 2.457 元/股 | 0 | 0 | 0% |

> 即：茅台当前口径的股息率分子**少计四分之一**。以 2026-09 价位粗估，约 **2.8 个百分点**的股息率被抹掉（估算，随价格浮动）。

### 3.3 与既有裁决的关系（为何原轮发现不了）

- **A1 只裁决了「纯送转行不落库」**（`cash==0 → None`），**未裁决「有派息但无报告期」**。当前实现把后者与前者**混为同一动作、同一计数**（摘要只报「无派息或报告期不可解析=N」），**无法区分**，属**静默数据丢失**。
- **与 Q4（§6 直删旧新浪 `SPECIAL` 存量）形成致命组合**：新链路**不产出** `SPECIAL`（因为特别分红行被丢），而旧新浪链路恰好能采到特别分红。**若先执行 §6 的直删，特别分红数据将从「有」变为「无」且不可恢复。**
- **构造数据单测无法发现**：P0 单测一律走构造数据（方案 §7 自述），构造样本的「报告时间」都填了值，因此 100% 覆盖率下该缺陷完全隐身。**这正印证了本轮用真实数据复测的价值。**
- 阿奇原轮的担忧（「新旧口径并存窗内靠 `_westward_dup` 与 `_covered_masters` 防重复计数」）在此**方向反转**：当前不是「重复计数」风险，而是**漏计**风险。

### 3.4 建议（需 owner 裁决，两选一 + 一条护栏）

| 方案 | 做法 | 代价 |
|---|---|---|
| **方案甲（推荐）** | 无「报告时间」但有派息的行，按**除权日所在年** + `report_quarter=4`（或专用占位）落库，`period_type` 记为准 `SPECIAL` | 需扩 §5.3 语义 + 唯一键兼容（`uq_security_dividends_master_period` 是 `master+period`，年+季占位可复用，但同一年多笔特别分红会撞键 → 需含 `ex_dividend_date` 参与去重） |
| 方案乙 | 维持丢弃，但在摘要中**独立计数并告警**（`report_period_missing_with_cash=N`），且 §6 旧数据**暂不删** | 数据仍缺，只是不再静默 |

### 4.1 闸门机制定性（修正原轮过度断言）

`check_line_budget.py:65-66`：`merge_base = git merge-base base_ref HEAD` → `git diff --numstat <merge-base>..HEAD`。

- **实测（基线落后时）**：`--base cnb/main`（bee1810c，是 HEAD 的祖先）→ **2118 行 > 800，EXIT=2**。
