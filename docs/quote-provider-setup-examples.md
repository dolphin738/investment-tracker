## 一、新增数据来源（小熊同学）

Base URL 整体归「数据来源」，该来源下的所有接口共用，不重复填。

| 表单字段 | 填写值 | 取值依据 |
| --- | --- | --- |
| 名称 | `小熊同学` | 文档标题后缀（对外展示名；系统已做重名校验，不可与现有重复） |
| 接入方式 | HTTPS（API 地址） | Base URL 为 https 接口地址 |
| API 基础地址 | `https://api.autostock.cn/v1` | 文档 Base URL（**只填到 /v1，不含 /stock**） |
| 描述 | 选填，如 `小熊同学行情接口（股票基础信息 / 所有股票）` | — |
| 启用 | 开（默认） | — |
| 设为默认 | 按需（禁用源不可设） | 全局回退默认方，至多一个 |
| 当前 | 按需（启用后方可选） | 系统当前使用的行情来源，全局至多一个 |

## 二、新增接口 1：股票基础信息（/stock）

路径、方法、参数归「接口」，调用时系统自动拼接 `数据来源.base_url + 接口.endpoint`。

| 表单字段 | 填写值 | 取值依据 |
| --- | --- | --- |
| 接口分类 | 下拉选已有分类（如「A股行情」） | 纯外键，只能选不能现建 |
| 名称 | `股票基础信息` | 文档接口标题 |
| 调用路径 | `/stock` | 文档路径（**只填 /stock，不含 Base URL**） |
| HTTP 方法 | GET | 文档方法 |
| 参数模板(JSON) | `{"code": "600000,000001"}` | 文档必填 Query 参数 `code`，多个逗号隔开 |
| 描述 | 选填，如 `股票基础信息：代码/名称/涨跌/开收高低/量额/PE/PB 等` | — |
| 超时(秒) / 重试次数 / 频率限制 | 选填 | — |
| 启用 | 开（默认） | — |

请求参数（Query）
- `code`（string，**必填**）：股票代码，多个用逗号隔开。示例：`600000,000001`

响应（200，信封结构）
```json
{
  "code": 0, "message": "", "traceId": "", "meta": {},
  "data": [
    {
      "code": "", "name": "", "type": "", "priceChange": "", "changePercent": "",
      "open": "", "close": "", "price": "", "high": "", "low": "", "volume": "",
      "volumeRate": "", "turnover": "", "turnoverRate": "", "PE": "", "SPE": "",
      "PB": "", "totalWorth": "", "circulationWorth": "", "date": "",
      "buy": [""], "sell": [""], "minData": [[""]], "requestFail": 0, "resolveFail": 0
    }
  ]
}
```

## 三、新增接口 2：所有股票（/stock/all）

| 表单字段 | 填写值 | 取值依据 |
| --- | --- | --- |
| 接口分类 | 下拉选已有分类（如「A股行情」） | 纯外键 |
| 名称 | `所有股票` | 文档接口标题 |
| 调用路径 | `/stock/all` | 文档路径 |
| HTTP 方法 | GET | 文档方法 |
| 参数模板(JSON) | `{}`（全量）或 `{"keyWord":"string"}`（模糊查） | 见下方说明 |
| 描述 | 选填，如 `小熊同学所有股票列表（支持 keyWord 代码/名称模糊查）` | — |
| 启用 | 开（默认） | — |

请求参数（Query）
- `keyWord`（string，**非必填**）：支持代码和名称模糊查询。

> 参数模板二选一（一个接口一份模板，不能两种同时塞）：
> - 填 `{}` → 系统调用 `GET /stock/all`（不带 Query），返回全部股票。推荐，因「所有股票」本职即全量。
> - 填 `{"keyWord":"string"}` → 系统调用 `GET /stock/all?keyWord=string` 做筛选。
> 若需同一来源同时支持两种用法：可建两个接口（同路径 `/stock/all`，靠模板区分用途）。

响应（200）
```json
{ "code": 0, "message": "", "traceId": "", "data": [[""]], "meta": {} }
```

## 四、关键拆分提醒

1. **Base URL 与路径分离**：`https://api.autostock.cn/v1` 进「数据来源」，接口只存 `/stock`、`/stock/all`。运行时系统拼接为 `https://api.autostock.cn/v1/stock?code=...`。
2. **同一来源多接口**：小熊同学来源下可挂多个接口（`/stock`、`/stock/all` …），无需重复建来源。
3. **信封一致**：文档响应的 `code/message/data` 结构与本系统后端契约吻合，无需额外适配。

---

## 五、参数模板填写注意事项

- 必须是**合法 JSON**，且用**半角**字符：花括号 `{}` 与双引号 `""` 都用英文半角。中文输入法误输全角 `｛｝` 或全角引号会被校验拦截（报「参数模板不是合法 JSON」）。
- 本系统已对「参数模板」输入框做容错：自动把全角花括号/引号、BOM、零宽空格归一为半角（见 `web/src/features/admin/quote-interface-dialog.tsx` 的 `normalizeJsonInput`），但养成半角输入习惯最稳妥。
- 不要将两个 JSON 拼在一起（如 `{} {"keyWord":"string"}`），那不是合法 JSON。
