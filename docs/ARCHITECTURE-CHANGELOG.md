## v2.9（2026-08-08 · 增量交易优化第二批 · INC-03/INC-04）

**变更说明（推翻 v2.8 费用「展示层聚合」方案，改为物理并表）**：将 v2.8 并入的「费用记录合并（I-03）」决策**反转**——原先「`fee_records` 独立表 + 展示层聚合（`grouped=1`）+ 保留明细行」方案（裁决 Q-8 / Q-2）被**推翻**，改为**物理并表（决策 A+F）**：`fee_records` 表 DROP，分项费用 `commission`/`stampTax`/`other`/`feeTotal` 收进 `security_trades`。**数据模型（schema.prisma）**：`SecurityTrade.price`→`costPrice`（含费单价，语义不变）、`fee`→`feeTotal`（= Σ三项，冗余展示列，决策 B/C-09 不回冲成本），新增 `commission`/`stampTax`/`other` 三列（DECIMAL(18,2)，缺省 0）；`FeeRecord` 模型移除、`FeeType` 枚举 DROP（`FeeScenario` 已非 DB 枚举——其 `"FeeScenario"` 类型由 batch2 `DROP TYPE` 删除；现仅作为前端 TS enum 存在于 `web/src/api/types.ts`，用于持仓统一筛选器 `scenario` 下拉，映射 `SecurityTrade.side`）。**迁移**：`20260807140302_tx_opt_batch2`（DROP fee_records / FeeType / FeeScenario + ALTER security_trades 加四列）；原 `20260808_add_fee_scenario`/`20260808_fee_scenario_enum` 两份作用于已删 `fee_records`/`"FeeScenario"` 的遗留迁移已于 2026-08-08 清理删除（详见主文档 §3.2.5）。**接口契约**：`/fees` 系列端点（GET/POST/PATCH/DELETE）及 `FeeService`/`FeeController`/`FeeModule` 全部移除；费用随 `SecurityTrade` CRUD 一并写入，`feeTotal` 服务端 `= Σ三项`。**前后端改动**：web `fee.api.ts`/`use-fees.ts`/`FeeRecord` 等契约删除，`security-trade-form` 直接编辑 `costPrice` + 费用三框（无 FeeRecord 拆分/回显/重建），`security-trade-list` 展示含费单价/费用合计/佣金/印花税/其他 + 买入金额(含费)/卖出金额(含费)/累计费用合计三卡；`dividend-fee-*` 收敛为纯分红；`holding-derivation.service` 成本口径改为 `costTotal += q * costPrice`（含费单价已含费）。**架构裁决反转**：Q-8（不采纳 DB 唯一约束→改为物理并表）、Q-2（FeeRecord 重建→作废）、Q-3（transactionIds 保留语义→失效）、Q-4（scenario 回填→仅筛选器）。**偏差登记关闭**：原 SET-P2-05（费用导出 scenario 列未落地）随费用表删除一并消解。**测试**：后端 security-trade.service.spec / holding-derivation.service.spec 对齐 Decimal 存储与含费单价口径，全量 479 测试通过；web 相关测试对齐新契约通过。**核实方式**：Read/Grep 比对 schema.prisma 与 migration、security-trade.service、shared/types、web 各 feature 实际代码。**未改动金融计算口径**：含费单价语义、成本不回冲决策不变；`finance-core` 零改动。
