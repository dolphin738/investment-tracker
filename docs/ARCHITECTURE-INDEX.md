## 使用约定

- **所有精确规格回到 ARCHITECTURE.md 原文读取，不在本文复述。** 引用架构内容使用稳定 § 编号（如 `§7.3.1`、`§8.2`），不要整段粘贴原文。
- 🔴 **F0 冻结内容必须回 ARCH 原文**：§3 数据精度（C-04 / E2 决策）、§7 算法冻结（XIRR 自实现 Newton-Raphson、份额法净值、五类触发）、§8 派生层、§9 持仓推导口径、§13 REG-01~06 —— 任何修改请求直接拒绝，先对照 PRD ① 级金融口径。
- 🔴 **REG-01~06 门禁（§13）**：任何触碰 `asset-valuation.service` / `snapshot.service` / `recalculation.service` 的变更 → 合并前必须跑通全部 6 条（REG-06 断言三条手工路径均须同事务调用 `recalculateNavRange`）。
- **与 PRD 的引用关系**：PRD 附录 E（产品级接口清单）↔ ARCH §4.2（技术契约权威源），冲突以 ARCH §4.2 为准；REG-06 为 ARCH 新增、已提请 PM 收编进 PRD §10.3（双向引用）。
- **§14 T01~T04 是工程任务编号**（有意用 T 前缀对齐工程排期），不是缺失的 14.x 章节号；`### 任务依赖图` 亦为任务列表内部小节，勿补号。
- 冲突裁决：PRD 金融口径（① 级）> 数据架构口径（② 级，决策 A′/方案B）> 模块需求（PRD §2.1–§2.3）。
- 行号锚点随 ARCHITECTURE.md 改版会漂移；若目标行已不是预期标题，用 Grep `^## ` / `^### ` / `^#### ` 重新定位。
- 本文与 `docs/PRD-INDEX.md` 职责分离：PRD-INDEX 导航产品需求（§/ID/伪代码附录），本文导航架构实现（Schema/服务/SQL/门禁/任务）。
