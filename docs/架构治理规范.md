## 1. 目录职责与禁止事项（§4.1-1）

### 1.1 后端 `backend/app/`

| 目录/文件 | 职责（一句话） | 禁止事项 |
| --- | --- | --- |
| `modules/` | API 路由层：参数校验、权限依赖、调用 service、分页 | 禁止写业务计算逻辑；禁止直接绕过 service 改 ORM 数据 |
| `services/` | 业务逻辑层：领域规则、跨实体编排、重算触发 | 禁止 import `app.modules`（路由层）；禁止构造**他域** ORM 模型（AST 检查） |
| `finance_core/` | 纯函数计算内核（xirr / nav / holding） | 禁止 import DB / ORM / HTTP / 配置；只做纯计算 |
| `models/` | ORM 表模型与枚举 | 禁止 import services / modules（不反向依赖上层） |
| `core/` | 横切关注（含 security/JWT/bcrypt、envelope、exceptions、enums、config、date_utils、rate_limit、scheduler、types、url_guard 等） | 禁止 import 业务层（services/modules/models） |
| `db/` | 引擎/会话/基类 | 禁止承载业务逻辑 |
| `schemas.py` / `schemas_resp.py` | 请求 DTO（*Req）/ 响应 DTO（*Out） | 禁止塞业务逻辑；金额字段统一 `DecimalStr`（定义于 `app/core/types.py`，序列化与 OpenAPI schema 均为字符串，对齐 Prisma Decimal 行为） |
| `serializers.py` | ORM 实体 → camelCase 响应 dict 纯函数 | 禁止访问 DB；禁止依赖路由层 |
| `storage/` | 文件/上传存储 | 禁止 import 业务层 |
| `common.py` | 路由层公共依赖：组合归属隔离（`get_portfolio`）、分页（`paginate`） | 禁止塞领域业务逻辑；仅 modules 可依赖（已由 `.importlinter` `bottom_no_common` 契约强制 models/services 不得反向依赖） |
| `main.py` | 应用装配、路由注册、lifespan | 禁止写业务逻辑；字面路由须先于参数路由注册 |

### 1.2 前端 `web/src/`

| 目录 | 职责（一句话） | 禁止事项 |
| --- | --- | --- |
| `api/` | HTTP 接口定义（axios 封装 + 各域 .api.ts） | 禁止写业务逻辑与组件状态；禁止 import components/modules |
| `modules/<域>/composables/` | 该模块的状态编排/查询封装（vue-query） | 禁止直接操作 DOM；禁止复用他域 composable 的行为逻辑；允许引用他域**常量/类型/queryKey** 及经显式再导出文件的符号（存量登记：use-query-data.ts:21 再导出 analysis 符号、use-portfolios.ts:27 取 PREFERENCE_KEY、use-security-prices.ts:27 取 priceSyncStatusKey，按上述分类豁免） |
| `modules/<域>/pages|components/` | 页面与展示组件 | 禁止绕过 api 层直接发 HTTP；展示组件禁止直接调 API（走 composable/api） |
| `components/` | 跨模块通用展示组件（含 charts） | 纯展示组件禁止 import `modules/*`；`components/layout/` 等**组合容器**可挂载业务组件（存量登记：AppLayout.vue:27-30 挂载 4 个 modules 组件、DateRangeQuickPicker.vue:40 引用 `query/quick-range`，为已知例外，待 §6 前端 AST 边界落地时豁免/重构） |
| `router/` | 路由与守卫 | 守卫只做鉴权/重定向，禁止写业务 |
| `pages/` | 跨模块全局特殊页（如 404 not-found） | 禁止放业务页面；业务页面一律进 `modules/<域>/pages/` |
| `stores/` | Pinia 全局状态 | 禁止放服务端数据的权威副本（服务端数据走 vue-query） |
| `lib/`、`constants/`、`types/`、`composables/`（全局，`src/` 下） | 共享工具/常量/类型/全局组合式 | 单向依赖：components/modules → lib 等，禁止反向 |
| `types/api.ts` | **生成物**（`web/scripts/gen-api-types.py` 产出；输入源 `docs/openapi.json` ← `backend/scripts/gen_openapi.py` 从 FastAPI app 导出） | **禁止手改**；改后端契约 → 重新生成（`python scripts/gen_openapi.py` + `python web/scripts/gen-api-types.py`） |
| `test-utils/` | 测试环境工具（jsdom polyfill 等） | 仅测试引用，禁止被生产代码 import |

> 边界的自动化现状：后端反向依赖由 `backend/.importlinter` + `tests/test_arch_boundaries.py`（AST）强制；
> 前端边界为约定 + knip 文件/依赖检测，尚未 AST 强制（见 §6 后续项）。
>
> 类型文件归属：shared 共用类型（值+类型双身份）进 `lib/types.ts`；API 本地请求/响应 DTO 进 `api/types.ts`（可从 `lib/types` re-export）；图表系列类型进 `types/series.ts`；`types/api.ts` 为生成物禁手改（见上表）。

### 1.3 仓库根级目录（§4.1"每个顶层目录一句话职责"）

| 目录 | 职责（一句话） | 禁止事项 |
| --- | --- | --- |
| `backend/` | Python 后端：应用代码在 `app/`，迁移在 `alembic/versions/`，OpenAPI 契约源脚本在 `scripts/gen_openapi.py` | 禁放前端代码/文档；禁改动开发库（`investment_tracker`） |
| `web/` | 前端：应用代码在 `src/`，e2e 在 `e2e/`，api.ts 生成脚本在 `scripts/gen-api-types.py` | 禁放后端代码 |
| `docker/` | 镜像构建与部署配置（Dockerfile / entrypoint / 生产 env 模板） | 禁放业务代码 |
| `scripts/` | 仓库级闸门/工具脚本（git 跟踪：pre_commit_gate.py、check_line_budget.py） | 本地一次性运维脚本不进此目录 |
| `dev-scripts/` | 本地运维脚本（git 忽略：push-all.ps1 等） | 禁放会被 CI 依赖的闸门脚本（CI 只能引用 `scripts/`） |
| `docs/` | 分析/方案/诊断 markdown | 归档落 `docs/archive/`、ADR 落 `docs/adr/`；常显 ` M` 但 diff 为空的 CRLF 假象文档勿纳入提交 |
| `uploads/` | 运行期上传数据目录 | 不入库 |

## 2. 调用边界（依赖方向，§4.1-2）

```
后端：
   业务依赖链：modules(routers) ──▶ services ──▶ models / finance_core
   横切依赖：任意层 ──▶ core（core 不得反向依赖业务层；已由 .importlinter `core_no_business` 契约强制，单点豁免见该契约 ignore_imports）
   底层设施：db（引擎/会话/基类）被业务各层（models/services/modules）广泛依赖，禁止承载业务逻辑；storage 仅被 services 引用，禁止反向 import 业务层
   禁止：models ─▶ services/modules；services ─▶ modules；finance_core ─▶ 任何 DB/HTTP/存储

前端： pages / components ──▶ composables ──▶ api ──▶ (axios)
        components(通用) ╳─▶ modules/*；types/api.ts 只读生成
```

## 3. 新增依赖准入（§4.1-3 + §4.3-2）

1. 新增任何依赖（Python / npm）必须在 PR/提交说明中回答：**「为什么现有依赖/原生能力做不到」**（人工自证）。
2. 前端由 knip 闸门强制：新增未使用依赖、未使用导出直接 fail（`web/knip.json`，CI `knip --include dependencies,unlisted,files,exports`）（自动）。
3. Python **核心运行时依赖**一律**钉死版本**进 `backend/pyproject.toml`（fastapi 等）；可选/懒加载依赖可用下限 `>=`，但**必须注明用途**（现状 akshare/pypinyin/apscheduler 即此模式）（人工审查）。
4. 依赖总数相对 main 增加超过 3 个时须在 PR 说明整体理由（人工自证）。
5. 已知豁免（knip `ignoreDependencies`）：
   - `postcss-load-config`——postcss 生态传递依赖，postcss.config.js 间接使用，声明入库需动 pnpm-lock，豁免并在此记录。
   - `@vitest/coverage-v8`（2026-08-31 新增）——前端覆盖率采集器，以 `provider: 'v8'` **字符串**形式被 vitest 引用，静态分析识别不到使用点（实测 knip 会报 unused devDependency 并让闸门 EXIT=1），故豁免；其存在性由 `scripts/check_frontend_coverage.py` 在运行时校验（缺失即退出码 3），不会因豁免而漏装。

## 4. 文件行数上限（§4.1-4）

- **新文件 ≤ 400 行**，超限需在提交说明中给出拆分理由。
- **存量超限文件禁止继续增长**：改动时鼓励顺带拆分；大拆（>100 行位移）单独立轮，不混入功能提交。
- 现存超限大户（阶段 4 时点基线，供后续瘦身参考；以 git HEAD 实测为准，季度复查时同步更新）：
  `app/services/market_data_sync.py`(1148)、`app/modules/admin/router.py`(828)、
  `web/src/types/api.ts`(1164，生成物不适用)、`web/src/modules/admin/pages/SchedulePage.vue`(902)、
  `web/src/modules/settings/pages/SettingsPage.vue`(884)、`web/src/modules/overview/pages/DashboardPage.vue`(775)。

> 口径提示：「400 行」为单文件物理行数上限（当前为人工约定、无自动闸门）；§8 的「>800 行」为单 PR 新增代码总行数预算（由 `scripts/check_line_budget.py` 自动强制）。两者维度不同，勿混用。
> 行数闸门按「新增代码」计：**所有 `.md` 文件均不计入**（非仅 docs/，脚本 `path.endswith('.md')` 全量排除），另排除锁文件（pnpm-lock.yaml / uv.lock 等）与二进制生成物（.snap/.svg/.png 等）。

## 5. 函数职责（§4.1-5）

- 一个函数只做一件事；禁止在既有函数里「顺手」加功能——新用途 = 新函数。
- 路由 handler 只做「校验→调 service→序列化返回」三段；复杂分支下沉 service。

## 7. 任务微型化纪律（§4.2）

大任务必须拆成多次小步对话/提交，每步只做一件事、可独立验证。示例：

- ✗ 错误：「给行情模块加稳定性保障」（重试+限流+超时+监控混一步）
- ✓ 正确：
  1. 只加 `_fetch_https_raw` 的超时参数，跑 `pytest -k resilience`；
  2. 只加重试（指数退避），补单测；
  3. 只加按接口 id 的限流，补单测；
  4. 同步状态暴露到 sync-status 端点，补端点测试。

## 8. 提交自动检测流程（§4.4）

每次 AI 生成代码提交前执行：

```bash
python scripts/pre_commit_gate.py            # 全量（ruff + import-linter + knip + 行数预算）
python scripts/pre_commit_gate.py --skip knip  # 离线快速模式
```

- 自动项（任一不过即打回）：未使用依赖/文件/导出（knip `dependencies,unlisted,files,exports`）、
  未使用 import/变量（ruff F）、架构边界（import-linter）、行数预算（>800 需 `LARGE_PR_APPROVED=1` 人工豁免）、
  后端分层覆盖率（`check_coverage.py`：finance_core 90 / services 60 / app 70，豁免 `COVERAGE_APPROVED=1`）、
  前端分层覆盖率（`check_frontend_coverage.py`：src/lib 73 / src 整体 65，豁免同前；**本地因 pnpm
  环境漂移装不到 `@vitest/coverage-v8`，由 CI 强制执行**）、
  前端类型门禁（`vue-tsc -p tsconfig.app.json` + `-p tsconfig.e2e.json`，CI frontend-lint 执行；本地可 `pnpm run lint` / `pnpm run typecheck:e2e` 预跑）。
- 告警项（打印但不阻塞，配环境变量升级为硬闸门）：产物体积增长 >5%（`check_bundle_size.py`，
  `BUNDLE_SIZE_STRICT=1` 转硬）、「缺测试」标记（`check_tests_touched.py`，`REQUIRE_TESTS=1` 转硬）。
- 耗时项说明：后端覆盖率（全量 pytest 约 4 分钟）、前端覆盖率（全量 vitest 约 1.5 分钟）与
  体积（`vite build` 约 1 分钟）由 CI 强制，本地 `pre_commit_gate.py` **默认跳过**（`SLOW_CHECKS`），
  按需 `--only coverage fe-coverage bundle` 显式执行。
- 人工项（脚本打印清单，提交人自证）：新增 export 至少一处使用（已由 knip exports 自动强制，清单保留作提交前提醒）、依赖准入说明、防御性垃圾（吞异常返回默认值/无意义重试/相似度 ≥0.9 复制块）、单一职责拆分。
- 测试仍按项目工作流单独跑（后端 `uv run pytest`、前端 `vitest run` + `vue-tsc`），闸门不替代全量回归。
