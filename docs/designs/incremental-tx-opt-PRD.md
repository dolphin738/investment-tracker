## 1. 背景与目标

### 1.1 背景

`investment_return_tracker`（投资收益统计系统）已上线，8 个受保护路由页面运行稳定。本轮针对**交易记录录入/展示体验**与**费用数据结构**收集到 5 项用户诉求，核心矛盾集中在三处：

- **默认日期范围未全站兑现**：设置了"默认日期范围"偏好，但**只有持仓页真正做到"初始即选中默认项 + 偏好异步到达后动态对齐"**；其余含日期范围的页面各有缺失 —— 概览页读偏好但无对齐（选中态冻结在首帧）、出入金/历史总资产的控件恒显示占位"选择范围"、XIRR/净值的内嵌范围 Select 同样恒占位。
- **日期范围控件本身就有两套（v1.2 新识别）**：4 个页面用共享的 `DateRangeQuickPicker`，XIRR/净值两页却用 `DimensionSwitcher` 内嵌的另一套「Select + 起止 Input」，外观与行为不一致，且是"选中态无法受控"的根因之一。
- **录入按钮同功能多种文案（v1.2 新识别）**：同为"打开出入金录入弹窗"，概览页叫「录入出入金」、出入金页叫「新增出入金」；历史总资产页按钮叫「＋ 新建记录」而其弹窗标题却是「录入资产记录」，用户易误判为不同功能。
- **费用数据双表分裂**：费用明细独立存于 `fee_records` 表、买卖流水存于 `security_trades` 表，展示时靠 `grouped=1` 展示层聚合。用户希望费用回到买卖明细中一处呈现，并对费用做**物理并表**（推翻既有架构裁决 Q-8）。
- **录入交互不统一**：买卖编辑弹窗标的字段回填失效（真实 bug）；各页录入按钮样式不一致。

### 1.2 本轮目标

| # | 目标 | 衡量口径 |
|---|------|---------|
| **T1** | 默认日期范围在**除持仓页外的 5 个页面**统一按持仓范式**可见且默认选中** | 5 个目标页面刷新后快捷范围控件均显示、初始值 = `defaultDateRange`，且偏好异步到达 / 变更后能动态对齐（用户已交互时不回弹） |
| **T1'** | **【决策 G】全站日期范围控件收敛为单一组件** | 6 个含日期范围的页面**只使用 `DateRangeQuickPicker` 一个控件实现**（当前为 2 套）；`DimensionSwitcher` 不再自绘日期范围 UI 且无死代码 |
| **T2** | 买卖记录编辑体验闭环 | 编辑任一买卖记录，标的字段自动带出且交互统一 |
| **T3** | 费用并入买卖明细、单表承载 | 费用列内联进买卖明细表；`fee_records` 表下线且无死代码（**决策 F：当前无存量数据，不涉及数据迁移与数据核对**） |
| **T4** | 录入按钮视觉与交互全站统一 | 各页录入主按钮与概览"录入买卖"完全一致 |
| **T4'** | **【决策 H】同一功能的录入按钮文案全站唯一** | 打开同一弹窗的按钮不存在两种文案（消灭「新增出入金」「＋ 新建记录」等异类）；按钮文案 == 弹窗标题；不同功能的文案差异保留 |

### 1.3 本轮明确不改动（红线）

- **不改任何金融口径**：XIRR、累计/当年净值、单位份额法、持仓 `avgCost`、含费单价计算公式一字不动（延续 PRD §3 / `FIN-*` / 附录 A、B 的 F0 冻结）。
- **不改分红逻辑**：`DividendRecord`、所得税 `tax`、净额 = 金额 − 所得税、红利再投口径不动（延续 `HOLD-B-P0-10` 分红部分）。
- **费用改造仅为"展示重构 + 数据来源切换"**：不做费用拆分重算、不动成本语义（决策 B）；且**不含数据迁移**（决策 F，无存量数据）。

## 3. 逐需求详述

### INC-01 · 默认日期范围全站兑现 + **日期范围控件统一**（P0）

**关联既有 ID**：`SET-P0-02`、`SYS-P1-03`、PRD §6.10.2 日期选择器审查矩阵（第 1~6 项）、`DASH-P0-02`、`FLOW-P0-02`、`CASH-P1-01`、`ANL-P0-04`、`ANL-P0-05`、`SNAP-P0-04b`；`HOLD-B-P0-11`（**范式来源**，本轮不改其行为）。

**用户故事**
> As a 用户，I want 在设置里设定"默认日期范围"后，除持仓页外的每个含日期范围的页面都像持仓页一样自动显示并选中该默认项、并在我修改偏好后自动跟随，so that 我无需每次进页面都手动重选时间范围。
>
> As a 用户，I want 全站所有页面的"日期范围"筛选器都是**同一个控件**（长得一样、选项一样、行为一样），so that 我不用在不同页面适应两种不同的时间筛选交互。

#### 决策 G（v1.2 新增 · **硬约束**）：全站日期范围控件收敛为**单一组件**

> 用户原话："**INC-01 里的控件也要统一，6 页不要再使用 2 个控件了**"。

**现状实证（代码探查，v1.2 复核）**：6 处日期范围控件分属**两套实现**——

| 控件实现 | 使用方（调用点） |
|---------|----------------|
| **`DateRangeQuickPicker`**（`components/date/date-range-quick-picker.tsx`） | 概览 `dashboard.tsx` L547、持仓 `holdings-toolbar.tsx` L111、出入金 `transactions.tsx` L372、现金余额变更历史 `cash-balance-history.tsx` L168、历史总资产 `snapshot-list.tsx` L212 |
| **`DimensionSwitcher` 内嵌的「快捷范围 Select + 起止日期 Input」**（`features/query/dimension-switcher.tsx` L212-270） | XIRR `xirr-analysis.tsx` L130、净值 `nav-analysis.tsx` L206（**全库仅此两个调用方**） |

**硬约束（本轮必须达成，非可选项）**

| # | 约束 | 说明 |
|---|------|------|
| **G-1** | **`DateRangeQuickPicker` 为全站唯一 canonical 日期范围控件** | 它功能更完整（受控/非受控双模 `quick`、`allRangeStart`、可配 label），定为唯一真相控件；**不得再新增第二个日期范围控件实现** |
| **G-2** | **`DimensionSwitcher` 内的日期范围部分改用 `DateRangeQuickPicker`** | 其内嵌的「快捷范围 Select」+「起始日期 / 结束日期 Input」三件套整体替换为 `DateRangeQuickPicker`；**`DimensionSwitcher` 自身保留**，继续承载「维度 Tabs（日/周/月/年）」与「聚合方式 Select」——**维度切换不在统一范围内，保留** |
| **G-3** | **6 页日期范围控件的外观 / 选项 / 交互完全一致** | 同一份 `QUICK_RANGE_OPTIONS`（7 项）、同一占位与回落规则、同一手动改日期后回落占位的行为 |
| **G-4** | **`DimensionSwitcher` 内那份重复的 Select + `QUICK_RANGE_PLACEHOLDER` 私有 state 一并删除** | 收敛后不留死代码（`dimension-switcher.tsx` L146-147、L157-158、L212-243、L246-270 相关分支） |

> **与既有 v1.1 结论的关系**：决策 G 是**加法**——"5 页按持仓范式（`useDefaultDateRange()` + 对齐 effect + 交互守卫）"与"持仓页只清 dead prop、行为不变"等 v1.1 结论**全部保持不变**，本次只额外要求"控件本体收敛为一个组件"。
>
> **对 Open Question #6 的收敛**：原问题"范式是逐页复制还是抽共享 hook"已被决策 G 部分回答——**控件层面必须单一组件**；hook 层面是否再抽 `useRangePreferenceSync` 仍留架构师裁决（见 §5 改写后的 #6）。

#### 决策 E：统一采用"持仓页完整范式"

本轮**不再逐页打补丁**，而是把已在持仓页验证过的实现范式**推广到其余 5 个页面**：

| ① | **统一读偏好** | 一律通过 `useDefaultDateRange()` 获取默认范围，不再各页直读 `getPreference('defaultDateRange')` | `HoldingsPage.tsx` L93 |
| ② | **初始即选中** | 快捷范围控件首帧回显值即 `defaultDateRange`（受控传入 `quick`，不得落占位"选择范围"） | `HoldingsToolbar` → `DateRangeQuickPicker quick={value.range}` |

**顺带清理项（持仓页 · 非 INC-01 主体）**

- **`HoldingsToolbar` dead prop `defaultRange`**：`HoldingsToolbarProps` 声明了该字段（`holdings-toolbar.tsx` L54）、`HoldingsPage` 也传入（L286），但组件解构中**从未使用**（L58-65）。本轮一并删除（props 声明 + 传参 + 相关测试桩），**不改持仓页任何行为**。

**口径 / 规则**

- 快捷范围选项统一取 `QUICK_RANGE_OPTIONS` 单一真相源 7 项：近一周/近1月/近3月/近6月/近1年/今年/全部（`1w/1m/3m/6m/1y/ytd/all`），不得新增第二份选项数组。
- **控件实现亦为单一真相源（决策 G）**：日期范围控件只允许 `DateRangeQuickPicker` 一个实现，不得新增第二份控件；`DimensionSwitcher` 收敛后不得再自持日期范围 UI 与私有回显 state。
- **维度切换（年/月/周/日）不属于"日期范围控件"**，`DimensionSwitcher` 的 Tabs 与聚合方式 Select 保留、行为不变，不在统一范围内。
- 生效优先级沿用既有：**URL 参数 > 用户偏好 `defaultDateRange` > 系统默认 `1y`**。用户手动切换后不得被偏好对齐逻辑弹回。
- `range=custom`（用户自定义起止）时控件回显占位属**预期行为**，不计为本轮缺陷。
- **持仓页不纳入本轮主体修改**：它已是范式来源，行为保持不变，仅执行上述 dead prop 清理。
- 本轮性质是"**兑现既有设计**"而非新增能力：PRD §6.10.2 矩阵第 1~6 项原标注 ✅（已接偏好默认），但实测**选中态**未达标；本轮补齐后矩阵标注方与实现一致（见 §5 Open Questions）。

## 6. 不做什么（Out of Scope）

- **不改任何金融口径**：XIRR / 累计净值 / 当年净值 / 单位份额法 / 持仓 `avgCost` / 含费单价计算公式全部不动（F0 冻结）。
- **不改分红逻辑**：分红记录、所得税、净额、红利再投、`DividendRecord` schema 不动。
- **不做费用拆分重算**：成本价 = 含费单价（决策 B），不把费用从单价里拆出来重算成本。
- **无日期范围的页面不加控件**：账户 `/account`、设置 `/settings`、登录页等不新增快捷范围控件。
- **INC-01 不新增任何快捷范围控件**：5 个目标页面均已有控件，本轮只修选中态与偏好联动 + **把 XIRR/净值的第二套控件替换为 canonical 控件**（1:1 替换，控件数量不增不减）。
- **决策 G 不改维度切换能力**：`DimensionSwitcher` 的维度 Tabs（日/周/月/年）与聚合方式（期末值/平均值）保留不动，只收敛其中的"日期范围"部分。
- **决策 H 不合并不同功能的按钮文案**：录入买卖 / 录入分红 / 录入出入金 / 录入资产记录是**四个不同功能**，各自文案保留；本轮只消灭"同一功能两种说法"。
- **决策 H 不改弹窗内的提交按钮文案**（「录入」/「保存」属表单动作，不在录入入口按钮范围）。
- **不改下拉菜单项形态的入口**：`portfolio-selector.tsx` 的「新建组合」与买卖表单标的下拉里的「新建标的」是 `SelectItem` 而非 Button，本轮不动（见 Q-H5）。
- **持仓页快捷范围行为本轮不修改**（决策 E：持仓页是范式来源，主体不动；**仅**清理 `HoldingsToolbar` dead prop `defaultRange`）。
- **不做任何数据迁移（决策 F）**：无迁移脚本、无存量搬运、无孤儿记录处置、无迁移前后数据核对 —— 因当前无存量数据。
- **标的价格内联编辑文本不改为按钮**（INC-05 不含）。
- **不改行情 / SecurityPrice / 现金余额业务逻辑**。
- **费用导出含场景列（`SET-P2-05`）本轮不新做功能**，仅在并表改造中确保其取数来源不被破坏（若需改造仅为适配并表字段）。
