# 季度股息抓取「抓到 1.4 万行却 0 落库」——诊断与修复

日期：2026-09-08　范围：`dividend_sync` / `dividend_period` / 迁移 0009 / 全局设置页四源下拉

---

## 1. 现象

手动触发系统任务「季度股息抓取」（2026-09-08 14:19–14:21，UTC 06:19:51–06:21:58）：

- 前端提示抓取失败；
- 日志中心新增两条：`job_run_logs` 一条（`status=SUCCESS`，message 末段 `2026Q4失败:'NoneType' object is not subscriptable`）、`app_logs` 一条 client error（reka-ui SelectItem 空值）；
- 实测库态：`security_dividends` = 0 行、`security_dividend_yields` = 0 行、`market_security_daily_prices` = 0 行（`securities` 11336 行）。

任务**实际跑完了**（后端记 SUCCESS），失败提示来自日志文案；真正的问题是**一条数据都没落库**。

---

## 2. 根因与证据链

### 🔴 A（主因）接口 `resp_code_field` 配置与源站列名不符 → 全量跳行

| 项 | 事实 |
| --- | --- |
| 接口配置 | 「东财-分红配送」`resp_code_field='code'`、`resp_name_field='name'` |
| 源站实际 | 走 akshare `stock_fhps_em`，返回列名为中文 `代码` / `名称`（`akshare/stock_feature/stock_fhps_em.py:55-86` 硬编码） |
| 代码路径 | `dividend_sync.py` `_upsert_dividend_batch` 与 `market_data_sync._prepare_master_rows` 均按配置字段 `row.get(...)` 取值 → 全为 `None` → 每行 `continue` |

**可回滚实证**（合成一个真实列名的分红行，跑 `_upsert_dividend_batch` 后 rollback）：

```
resp_code_field='code'  → mids = []                       # 0 落库
resp_code_field='代码'  → mids = ['5c61cfc6-ef83-5a93…']   # 正常
```

**为何 seed 没兜住**：迁移 `0004_dividend_yield.py:120` 写的本是 `'代码'/'名称'`（正确），但用 `WHERE NOT EXISTS(name)` 幂等保护 —— 开发库该行是旧库遗留（id 为 32 位无连字符 hex），seed 跳过、未纠正，形成数据漂移。

### 🔴 B 报告期网格包含尚未进入的期次 → akshare 崩溃

`_pending_periods` 网格 = `range(cur_year-4, cur_year+1) × Q1..Q4`，2026-09-08 会生成 **2026Q4**（报告期 2026-12-31）。东财对未来 `REPORT_DATE` 返回 `result=null`，akshare `stock_fhps_em.py:45` 直接 `data_json["result"]["pages"]` → `TypeError: 'NoneType' object is not subscriptable`，与日志逐字一致。

### 🟡 C 失败被吞 + 摘要口径掩盖零落库

- 单期失败只拼进 `summary` 字符串，异常不上抛 → 整体仍记 `SUCCESS`；
- 摘要只报**抓取行数**（如 `2022Q4(3482)`），不报落库条数 → 「抓 1.4 万、落 0 条」全程静默。

### 🟡 D（附带）前端 `SelectItem value=""`

`GlobalSettingsDividendTab.vue` 四个接口下拉的「不设置」项用 `value=""`，reka-ui 在 setup 阶段抛错并上报前端错误日志。项目本已有哨兵约定（`web/src/modules/query/quick-range.ts`），此处未复用。

## 3. 修复清单

| # | 修复 | 位置 |
| --- | --- | --- |
| A-1 | 迁移 0009：幂等 `UPDATE` 把该接口行纠正为 `'代码'/'名称'` | `alembic/versions/0009_fix_dividend_interface_code_fields.py` |
| A-2 | `_code_of()`：配置字段取不到时回退中文列名（最后兜底） | `app/services/dividend_sync.py` |
| B | 新增 `current_quarter` / `is_future_period`；`_pending_periods(today)` 过滤未来期次 | `app/services/dividend_period.py`、`dividend_sync.py` |
| C-1 | 任一期失败即 `raise RuntimeError`（任务正确记 FAILED） | `dividend_sync.py` |
| C-2 | 摘要改报「抓 N / 落 M」；抓到行却零落库打 WARNING | `dividend_sync.py` |
| D | `SELECT_EMPTY_VALUE` 上移至 `lib/constants.ts`，四处下拉改用哨兵 | `web/src/lib/constants.ts` 等 4 文件 |

**判据取舍**：`is_future_period` 用「严格晚于**当前季度**」而非「晚于报告期结束日」。后者会把当季（2026-09-08 查 2026Q3，结束日 09-30）误判为未来，而实测当季已有 9 行披露数据，误伤会导致漏抓。
